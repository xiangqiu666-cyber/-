# 分歧指数 · 自动抓取版

前端选比赛 → 后端自动抓取 500.com 百家欧赔 → 自动计算胜/平/负分歧指数。**全程不需要手工输入任何赔率。**

## 启动

```bash
pip3 install flask requests
python3 server.py
# 浏览器打开 http://127.0.0.1:8777
```

点「抓取赛事」→ 选联赛/搜球队 → 点任意一场比赛 → 自动出结果。

## 文件

| 文件 | 作用 |
|---|---|
| `server.py` | Flask 服务：抓取 + 解析 + 分歧算法 |
| `index.html` | 前端页面 |
| `.cache/` | 网页缓存（默认 5 分钟，避免频繁请求源站） |

## 数据源

- 赛事列表：`https://live.500.com/?e=YYYY-MM-DD`
- 百家欧指：`https://odds.500.com/fenxi/ouzhi-{fid}.shtml`（服务端渲染，含每家公司的初盘/即时赔率、概率、返还率、凯利指数）

## API

| 接口 | 说明 |
|---|---|
| `GET /api/matches?date=2026-11-01` | 返回比赛列表（fid / 联赛 / 时间 / 主客队 / 让球 / 比分） |
| `GET /api/divergence?fid=1419241` | 欧赔分歧（`&trim=1` 剔除异常公司） |
| `GET /api/divergence?fid=1419241&market=ah` | **让球（亚盘）分歧**：主流盘口、盘口分歧（std）、主赢概率水位 CV（全部/主流盘口内）、逐家初盘与即时盘 |
| `GET /api/divergence?...&hg=1&ag=0` | 附加比分后返回 `validation`：实际赛果 vs 最小分歧方向（命中/未中）+ 全市场看好方向一致率 |
| `GET /api/backtest?date=2026-10-31` | **整日复盘**：全部完场比赛的命中统计（欧赔/让球），并发抓取，首次约 10-20 秒 |

盘口显示口径：**「让球方 -x」**——主队让 0.5 显示为 `主队 -0.5`；主队受让 0.5 显示为 `客队 -0.5`（等价于旧的"主队 +0.5/受半球"）；平手为 `平手 0`。

返回示例：
```json
{
  "companies_used": 24, "companies_total": 24,
  "items": [{"label":"胜","cv":0.0247,"mean_prob":0.3695}],
  "open_cv": [0.0394, 0.0180, 0.0520],
  "detail": [{"name":"B*****","alias":"Bet365","open":[2.38,3.1,2.9],"live":[2.6,3.2,2.7],"fair":[...],"z":[...]}],
  "consensus": "平"
}
```

## 算法

1. 每家公司赔率 → 隐含概率 `1/赔率` → 去水（除以三项之和，消除返还率差异）
2. 对每个赛果，计算 N 家公司公平概率的**标准差 ÷ 均值**（变异系数）= 分歧指数
3. 同时算初盘分歧作对照：`即时 < 初盘` 表示市场走向一致，反之表示分歧扩大
4. σ = 该公司偏离全市场均值的标准差倍数，>2σ 标记为异常公司（可选剔除）
5. **今日分位基线**：`/api/rank` 计算整日分歧时落盘一份 cv 池（`.cache/cvpool_*`），单场详情据此返回 `pct`——即该场分歧在当日全部比赛中的百分位（P30 = 比当日 70% 的比赛分歧更小）。解决「0.08 究竟算高算低」的绝对阈值问题；样本不足 5 场时返回 null，前端会自动后台补算一次当日全量。

**让球分歧口径**：亚盘各家盘口可能不同，直接比水位没有意义，因此分两个指标——
- `line_std`：即时盘口（主队视角，负=让）的标准差；`off_line_count` = 与主流盘口不同的公司数
- `cv_all`：主队赢盘公平概率的变异系数（混入盘口差异）；`cv_majority`：只取开出主流盘口的公司再算一次（纯水位分歧，更可比）
- 前端明细表列出每家初盘/即时「主水/盘口/客水」及相对主流盘的差值

## 战绩库（跨日检验）

每次 `/api/backtest` 复盘都会落盘一份当日明细（`.cache/hist_{date}.json`），`/api/history` 汇总成累计战绩库，用来检验这工具的全部前提：

- **对照组**：除了「最小分歧方向」，同时统计「市场看好方向」（概率最高项）的命中率——只有跑赢这个简单基准，分歧指数才有意义
- **分档检验**：按一致性分位切成 P0-25 / P25-50 / P50-75 / P75-100 四档，看命中率是否随「更一致」单调上升

### 当前累计（27 天 411 场）实测结果

| 口径 | 最小分歧方向 | 市场看好方向 | 最一致档 P0-25 | 分歧最大档 P75-100 |
|---|---|---|---|---|
| 欧赔 | 53% (218/410) | **56%** (228/410) | **63%** | 39%（单调下降 ✓）|
| 让球 | 49% (187/380) | 同左（两方向等价）| 51% | 47%（**无单调性**）|

**重合 / 交叉筛选（欧赔，最有价值的部分）**

| 子集 | 场次 | 命中率 |
|---|---|---|
| 最小分歧 = 市场看好（重合）| 283 | **61%** |
| 两者冲突 | 127 | **36%** |
| 重合 ∩ 最一致档（最优子集）| 76 | **67%** |
| 冲突 ∩ 分歧大档（最差子集）| 57 | **26%** |

结论：

1. **欧赔分档假设成立**：命中率随一致性单调下降（63% → 59% → 55% → 39%），但整体仍略输简单基准「押市场看好」
2. **重合是最强过滤器**：重合 61% vs 冲突 36%，冲突场次应当直接放弃而非二选一；叠加最一致档后达 67%
3. **让球口径的早期结论已被推翻**：93 场时曾显示 65% vs 42% 的区分度，扩大到 411 场后消失（51/57/43/47 无规律）——这就是必须跨日累计的原因，小样本结论不可信

> 注：复盘用的是当日缓存的即时（多为终盘）赔率，与实盘赛前看到的赔率存在口径差异；样本越大结论越稳，建议持续每日复盘。

## 说明与限制

- 公司名来自站方掩码显示；`alias` 是按「首字符 + 字数 + 注册地」唯一确定的推测名，仅供参考
- 赔率每家公司更新频率不同，页面已显示各公司最后更新时间
- 如需历史时点（赛前 24h/12h…）的分歧走势，需自行扩展为定时轮询并落库存快照

⚠️ 仅供数据学习研究，不构成投注建议；境内参与境外博彩属违法行为。

## 24 小时常驻运行

当前预览链接依赖沙箱环境，沙箱休眠后会失效。要真正 24 小时可用，任选一种：

### 方案 A：部署到免费云平台（推荐，不用自己开电脑）
仓库已备好 `requirements.txt` / `Procfile` / `runtime.txt`，可直接部署：

| 平台 | 免费额度 | 步骤 |
|---|---|---|
| **Render** | Web Service 免费（15 分钟无访问会休眠，首次访问约 30 秒唤醒） | New → Web Service → 关联仓库 → Build `pip install -r requirements.txt` → Start `gunicorn server:app --bind 0.0.0.0:$PORT` |
| **PythonAnywhere** | 免费账号 1 个 Web App，常驻不休眠（需每天点一次续期） | Web → Add new web app → Flask → 上传 `server.py` / `index.html` / `requirements.txt` |
| **Railway / Fly.io** | 按月免费额度 | 关联仓库，自动识别 `Procfile` |

注意：部署后要能访问 `live.500.com` 与 `odds.500.com`（海外节点一般正常）；环境变量 `PORT` 已支持，无需改代码。

### 方案 B：自己的机器 24 小时开着
在常开的电脑或 NAS / 云主机上：

```bash
cd /workspace/分歧指数
pip3 install -r requirements.txt
gunicorn server:app --bind 0.0.0.0:8777 --workers 2 --threads 4 --timeout 120
```

- 同 WiFi 用局域网 IP 访问；需要外网访问则配路由器端口转发或 frp/ngrok 内网穿透
- 用 `systemd` 或 `supervisor` 守护，崩溃自动重启
